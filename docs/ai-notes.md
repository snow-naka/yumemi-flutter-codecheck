### 主な設計判断

**HTTP通信と状態管理**

- Phase 1で採用したNotifier版検索Controllerを維持し、GatewayをFakeから実HTTP実装へ切り替えた。
- HTTP Client、要求キュー、タイムアウト、送信前キャンセルを管理し、不要になった非同期応答を検索状態へ反映しない。
- HTTPエラー分類と、次回のHTTP送信を許可するかどうかの判定を分離した。
- Primary・Secondaryレート制限、Retry-After、リソース別の待機期限を管理する。サーバーから通知された期限が複数ある場合は、長い方を維持する。
- Fake GatewayとMock HTTP Clientを自動テスト用に維持した。

**API診断**

- Debugビルド専用のAPI通信インスペクターを追加した。

- 利用者が確認したいのは主にAPI利用制限の状態であるため、レスポンスJSON全文の保存・表示は採用しなかった。
- 診断履歴は件数を制限し、HTTPステータス、レート制限情報、再送待機時刻など必要な情報に限定した。

**詳細表示とIssue数**

- オーナーアイコンはGitHub APIから取得した画像URLを使用する。URL不正や画像取得失敗時は代替アイコンを表示する。

- 詳細画面を開くたびに追加のSearch API要求を発生させると使い勝手が悪くなるため、PR除外Issue数の自動取得は採用しなかった。
- 二重送信を防ぎ、詳細画面から戻る操作が成立した後は、未送信のIssue検索要求をキャンセルする方式を採用した。

### 独立レビューと修正
